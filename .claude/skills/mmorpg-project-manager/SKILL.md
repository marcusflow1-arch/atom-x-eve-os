# MMORPG PM operations

Read root CLAUDE.md first and preserve its restrictions. Read `docs/mmorpg-agent-team/README.md`, WORKBOARD, OPEN_DECISIONS and all actual submitted reports. Ensure owner has selected the exact game before creating implementation tasks.

Create one task ID, owner, nonoverlapping file scope, branch, acceptance test and report location per assignment. Audit combat, factions, forge, mounts, stats, economy, netcode, UI and persistence boundaries. Request versioned contracts for cross-system changes. Verify observed evidence; return incomplete work for rework, send passed work to independent QA. Do not claim to have messaged other chats without an action.

At end, publish PM status: complete, blocked, conflicts, QA result, work left, release approval state and exact next prompts. No self-approval or unapproved direct merge/deploy.
